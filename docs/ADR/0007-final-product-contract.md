# ADR-0007：Robot 测试域与三端契约优先

- 状态：历史决策。最终产品方向由 [ADR-0010](0010-ai-workspace.md) 接替。下文记录 2026-11-17 决策时的内容。
- 日期：2026-11-17
- 基线：main 41ef74c；关联 ADR-0003/0005/0006

## 问题

原 UI 将工作台和 AI 提问入口混为一体，缺少知识库和登录等完整页面。三端仅有通用业务 CRUD，尚未区分 Robot 用例定义、筛选快照、运行结果。用户要求依据提供的并行测试系统背景，现在确定最终产品和 server/AI/Web 契约，避免独立开发漂移。

## 决定

1. 最终产品为智能电表 Robot 测试智能协作层。工作台管理项目状态和待处理事项；AI 助手负责查用例、查规范、解释已导入结果和形成建议。提供完整登录、知识库/文档、套件/用例、运行、导入、草稿和项目管理设计。
2. 保留 v1 登录和既有 CRUD，新增项目隔离等业务统一 `/api/v2`。不把数字 ID、字符串 tags、全体认证用户可读的旧用例接口直接改成新语义。内部服务保持独立 `/internal/v1`。
3. docs/contracts 的版本化 OpenAPI + Draft-07 schema 为唯一跨端契约。固定 DTO、权限、状态、错误、幂等与事件重放；页面和工具使用 operationId 映射，自动门禁验证。
4. Robot 目录和 output.xml 使用受限静态解析；业务数据、选择语义、授权与写入由 Java 统一决定。RAG 只处理知识依据，不能代替 Suite/Tag/Run 精确查询。
5. 只接自造/有权使用的导入材料和独立模拟域，不配置原企业接口，不让模型运行 Robot、Shell、SQL 或真实台体。
6. 本次完整冻结设计，不要求一次实现所有后端服务；正式原型和示例明确为设计验证，新增运行功能保持 PLANNED，避免用假接口冒充已交付。

## 代价与替代

v2 增加一个迁移边界，但消除静默破坏既有 v1 行为的风险。放弃“只改页面、随后各端自定字段”的方案；也不先搭建空服务/空数据表。基于已锁定 Ajv 6.15.0 做契约自身校验，真实 provider 校验在各业务切片接入，不能把静态校验说成联调通过。

## 结果

开发入口：[最终设计](../PRODUCT_DESIGN.md)、[契约](../contracts/README.md)、[领域模型](../DOMAIN_MODEL.md)。改语义先更新契约和本 ADR 的后继决策，再改三个消费方。
