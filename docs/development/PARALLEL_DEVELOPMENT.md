# 三端执行入口与最终版联合验收

适用 2026-11-19 最终工作台基线。先读[总计划](../ROADMAP.md)和[新契约](../contracts/README.md)。业务涉及四个角色、一个项目、一份有两个版本的技术规范、一份共用标书、一条 Robot 运行、一个私人会话。共同 fixture 在 [workspace.examples.json](../contracts/workspace.examples.json)。兼容客户端不得使用新版行为替换现行 DTO。

## 启动和交接

集成方在 G0 对照页面、字段、权限矩阵和六项已确认规则，按 2.0.0 交付。公共契约/样例/跨端测试归集成方；三个工作区各自在本域改动，按仓库协作约定与授权同步。每次交接记录“任务号、提交基线、真实调用的 operationId、输入、实际返回、失败/跳过、下一个消费方”。开工提示可直接复制到对应会话：

- **Web**：读取 WORKSPACE_WEB.md 及其链接，从 W1 开始完成改造和最终版 W1–W8。以工作台 OpenAPI 为唯一新业务输入。用逐页验收表核对按钮、角色、状态和来源。每步先验证消费者再接真实 provider。只改 Web 与本域记忆。
- **Server**：读取 WORKSPACE_SERVER.md 及数据模型，执行 S1–S7。收紧现有 admin 旁路与旧接口，完成迁移、权限、事实、对象授权、索引/运行编排、会话事件与引用注册。用真实 MySQL/Redis 和正式内部 HTTP 验证各步骤。只改 Server 与本域记忆。
- **AI**：读取 WORKSPACE_AI.md 和内部契约，执行 A1–A7。保留解析与索引，通过真实 Java 授权对象读取。完成各级证据、双版本判定、Robot 草稿、评测、模型和 Embedding 接入。只改 AI 与本域记忆。

每端的单元/契约替身可并行，业务闭环串行放行。发生消费者/提供方差异时提交最小请求、响应和 requestId 交集成方更新唯一契约，各端重新跑同一例。未确认的字段不能成为生产默认。

## 可以执行的检查

从仓库根目录运行：

```powershell
. ./scripts/env.ps1
node tests/contracts/workspace-review.cjs
npm run contracts:check
./scripts/check.ps1
```

第一条 Node 检查编译新契约模型、对照路径/权限/写入幂等约束、双版本回答和错误输入。npm 命令检验当前应用依赖的兼容契约。两类检查都不启动正式业务。

集成方在 G0 把新契约自检加入 CI；G2 准备 Java 对象根目录和持久化索引目录、Java/AI 两套服务签名与验签材料、各自的 issuer/audience。Python 现有设置包括 TESTOPS_AI_SERVER_BASE_URL、TESTOPS_AI_SERVER_PUBLIC_KEY、TESTOPS_AI_PRIVATE_KEY、TESTOPS_AI_INGESTION_STATE_DIR、TESTOPS_AI_EMBEDDING_PROFILES、TESTOPS_AI_QDRANT_URL。由 S3/A1 在部署配置显式配对；A4 接入真实回答模型时增加服务端模型 endpoint、model ID 和密钥设置，并更新示例与启动验证。配置变量只存端点/密钥引用，Web 包内不得包含模型凭据。G5 在隔离环境验证持久卷、重启恢复、日志脱敏、备份恢复、旧 UI 切换不恢复旧的越权路径。

正式实现 G4 后，在独立的联调库和对象目录部署 Java、Python、Web、MySQL、Redis、Qdrant，配置内部签名/验签、模型与 Embedding。先用各服务健康探针和 `scripts/smoke.ps1` 验证网络，完成四个测试账号登录。向当前终端注入 TESTOPS_REVIEW_BASE（Nginx 地址）及 TESTOPS_REVIEW_ADMIN_JWT、TESTOPS_REVIEW_OWNER_JWT、TESTOPS_REVIEW_TEST_JWT、TESTOPS_REVIEW_DEV_JWT 后运行：

```powershell
node tests/contracts/workspace-live.cjs
```

实测脚本在目标环境新建唯一验收项目并保留其记录，覆盖 J1–J5 的主链及 J6 的私聊隔离检查。它用真实 HTTP 创建、登记、轮询、订阅 SSE、验证两版结果/来源，再撤权限并检查旧引用。未配置账号或 provider 会明确失败。J2/J3 的其他格式和错误分支、J6 浏览器与 J7 的恢复/竞态须由对应端补齐 fixture、provider 与浏览器回归并独立签收。采用隔离环境生命周期清理测试数据。报告只列项目 ID、请求号与断言结果。

**签收记录**：每个 J 编号记录 Git SHA、迁移版本、服务/模型配置标识、参与角色、请求/响应状态、证据位置及真实依赖/替身/跳过项。只有 J1–J7 都通过才对外标记最终版真实三端联调通过。
