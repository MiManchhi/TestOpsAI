适用 codex/ai-ingestion，写 apps/ai-service 与本域记忆。先读[原始业务](../references/2026-11-17-robot-framework-background.md)、[接口](../contracts/README.md)、[联合验收](PARALLEL_DEVELOPMENT.md)。Python 管静态解析、知识检索、解释与 Robot 草稿；数据库权限、业务登记、最终引用由 Java 管。

## B · 最终版推理、生成与真实服务验收

| 顺序 / 依赖              | 具体实现                                                                                                                                                                                                                                                                                                                                                            | 验收                                                                                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A4 · S3/S4 对接          | 在实际需要时增加对话域，注册 composeAnswer。任务意图覆盖文档问答、审阅粘贴用例、按要求生成/补写、按运行排查。文档+授权版本精确过滤检索，按 resolveEvidence 获取观测事实；仅把最少的脱敏证据交给模型。                                                                                                                                                               | 普通成员输入无需选择索引库；多次复测不明确时请求澄清；无范围直接返回资料不足。模型提示里的伪指令无业务副作用。私有附件只归当前对话。                                     |
| A5 · 判定与 Robot 草稿   | 使用项目历史/当前各一个可见包，在同包多份文件中逐条定位。包内冲突标明待确认，受限文件不传给模型。按 AT_RUN/CURRENT/DESIGN 组织 findings。区分脚本状态、期望、实测、证据与推测。数值比较标准化单位后确定性计算；条件含糊、单位不明、缺版本或日志时返回 INSUFFICIENT/NEEDS_CONFIRMATION。Robot 草稿以文本输出；没有受支持的关键字或参数时用注释 TODO 并列入 pending。 | 示例 2.5 s 对 3 s/2 s 给相反结论，边界 2.0 对 ≤2 达标，缺计时保持未知。每条判断有候选来源 locator；拒绝虚构定位。不产生最终 citationId、不执行脚本、不写正式用例。       |
| A6 · 错误恢复与评测      | 设置检索/生成/工具超时和取消传播；服务不可用有稳定错误，不把替身回答当成功。标准化中文短结论与证据；用一组固定的自造输入、预期来源、期望判定、禁止出现的结论组成回归集。                                                                                                                                                                                            | 至少覆盖五类正向任务、版本冲突、未指定依据、无权限、撤权、恶意文档、无证据、依赖不可用。建立真实模型+Embedding+Qdrant 的隔离测试通道；证据可追踪 model/profile/version。 |
| A7 · J2/J4/J5/J6/J7 联调 | 与 Java 用真实服务令牌、授权对象、version allowlist 与运行样例走完整链；与 Web 验证复制后的 Robot 片段、资料引用、失败提示和回到原对话。                                                                                                                                                                                                                            | 固定用例任一未授权证据泄露、虚构验收结果或伪造出处均判失败。报告每个输入结果和引用命中，无真实模型时标出未验证项。                                                       |

在 apps/ai-service 执行 `uv run --locked ruff check .`、`uv run --locked ruff format --check .`、`uv run --locked mypy`、`uv run --locked pytest`；真实服务配置和独立检查参考 [解析说明](AI_PARSER.md)、[索引说明](AI_INGESTION.md)。根目录另跑 `node tests/contracts/workspace-review.cjs`。

**给执行 AI**：从首个未完成 A 编号开始验证现有能力，只在对应域补缺。向 Java 提供真实请求/响应、失败语义、可复现 fixture 和 requestId。先做证据正确性，再验真实生成质量，分别标明替身和生产协议的覆盖。

### 模型请求和校验规则

- 服务端显式配置 TESTOPS_AI_CHAT_BASE_URL、TESTOPS_AI_CHAT_MODEL、TESTOPS_AI_CHAT_API_KEY。ModelClient 使用部署方提供的兼容聊天 HTTP 协议，向 base URL 下的 `chat/completions` POST，使用服务端 Bearer、model、messages 和 JSON 对象输出模式。适配器读取 choices[0].message.content，再用 Pydantic 严格校验；部署 smoke 必须验证此响应形状。接口不通或返回非法结构时报告依赖失败，调用方不得把错误改写成业务达标。
- 系统提示固定声明任务、字段和判定规则；证据作为数据列表传入，每项使用当前请求内的短编号、可见原文与定位。用户附件、原文中的指令作为引文处理。模型返回短编号和文本，程序只从本次证据字典映射来源；不存在的编号、引文不符或标签越界即丢弃该结论。不给模型对象地址、服务令牌、工具执行能力或整个项目索引。
- 以现有 15 秒检索预算为上限，单次模型调用上限 45 秒，整轮上限 120 秒；瞬态 429/503 在余量允许时重试一次，必要时尊重 Retry-After。减少上下文时先裁旧历史和重复片段，保留双包原文及关键测量；裁剪使判断缺证时明确标注。每次 HTTP 设置 connect/read 截止，传播取消。Java 收到终态后丢弃迟到结果。日志只记请求号、模型标识、耗时、命中数量和安全错误码。
- Robot 草稿输出包含 Settings/所需资源说明、Test Cases、准备、执行、断言及清理（适用时）。优先复用已核实的项目关键字和参数；未知项用注释 TODO 并列入 pending，无项目关键字时不可声称草稿可实际执行。用户复制时附条款和缺口，不新增正式用例实体。

| 输入                                                   | 期望                                                                                   | 不能出现                         |
