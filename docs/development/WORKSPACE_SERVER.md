### 数据库实施顺序与约束

在 `src/main/resources/db/migration` 紧跟当前最高号向前迁移。以当前 V8 为起点，依序为账号与成员、资料与对象、验收包、运行、会话与作业。下列为目标表逻辑名，新旧同义表应在迁移脚本明确复用、扩展或回填。默认主键 BIGINT、外键同类型，公开 UUID 用 BINARY(16)，hash 用 BINARY(32)，时间 DATETIME(6) UTC，revision BIGINT。状态写入用 CHECK，跨行不变量在同一事务检查。[迁移规则](../DOMAIN_MODEL.md)约束存量角色映射。

| 逻辑表                                                         | 最小字段与索引                                                                                                                                                                                                                                                                                                                                                                        |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| users / projects / project_members / owner_transfer            | users 增凭据修订、强制改密及启用状态。projects 增 owner_user_id、revision、auth_revision、basis_revision、current_basis_id；成员保留 (project_id,user_id) 主键、项目身份与 revision。owner_transfer 持久化 Handover 全字段，pending_project 由 PENDING 时取 project_id 否则 NULL 的可空生成列加 UNIQUE，历史索引 (project_id,created_at,id)。所有管理写附操作者与前后值审计。         |

### Worker、恢复与交付测试

1. 短事务 `SELECT … FOR UPDATE SKIP LOCKED` 领取到期工作，写租约并提交，再发 HTTP。用稳定业务键或契约的稳定任务标识重交同一尝试。读写 cursor、生成向量和块导入均须可重放；重启先认领过期租约、查已知 jobId。重复块若同 locator 内容不同，标记失败并保留旧指针。
2. 暂时性 429/503/连接中断按 1、4、16 秒退避，受总截止时间约束。格式、hash、授权或过期依据拒绝不盲重试。任务失去授权后停止派发；每次下载及证据回读重新鉴权。用 requestId 串联作业与轮次。无外部依赖的监控只读 job 投影。
3. 在真实 MySQL 上查断言：拒审后 job 数为零；批准并发只出一条 INDEX；两次并发 setBasis 相同 revision 恰一成功；任意时刻恰一负责人；READY 的块数和 hash 对应同一作业；每个 turn 恰一终态。用假时钟覆盖生效边界、回执过期、租约重领。再跑 J1–J7 的真实 HTTP 与浏览器证据。
4. 每个 S 交付对应 Controller 的允许/拒绝两条请求和一次异常恢复。使用真实事务覆盖「写入后网络断开」「Python 完成后 Java 重启」「撤权时正在回答」；MockMvc 验证 JSON 与权限，隔离容器验约束和锁，不以 H2 推断 MySQL 行为。

迁移实施前逐项对比 HTTP schema 长度、数据库列宽和旧角色 CHECK；例如 V6 的 projects.name 为 VARCHAR(128)，新契约上限 160，须在新迁移扩列并测 160/161 字边界。不可将未映射的旧 VIEWER 默认升为可写角色。V2 内部签名配对与 scopeDigest 跨语言金样本见[接口约定](../contracts/README.md#内部服务身份的配对)和[样例](../contracts/workspace.examples.json)。
