# AI 会话入口与并行协作

更新：2026-11-17。状态：IMPLEMENTED（仓库规则；客户端新会话实测另行记录）。

## 一份入口，动态恢复

根 [AGENTS](../../AGENTS.md) 是唯一仓库指令入口。Codex 与本机已检查的 DeepSeek Harness 0.2.2-rc.3 都支持加载此文件，不新增 CLAUDE.md、子目录 AGENTS 或不同内容的客户端规则副本。

Codex 在启动时构建指令链，见 [官方指南](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。本机 Harness 安装包中 `@deepseek-ai/dsh-agent-instructions/README.md`、`src/config.ts`、`src/index.ts` 显示：dsh-base 默认启用加载器，首次模型请求前加载项目指令，默认候选包含 AGENTS.md；profile 可关闭加载，且存在内容预算。该结论来自安装包静态核查，不代表当前 profile 或真实新会话已经验收。Harness 不持续监视外部编辑，切换工作目录会重新加载；因此持续会话在任务切换、规则更新、同步主线、恢复或压缩后仍须主动重读。

用户只需从正确 worktree 打开会话并给出目标，例如“继续 WEB-001”。AI 应自行执行 `scripts/memory.ps1 -Mode Restore -ListOnly`，按清单分批完整读取最新文件，避免单次输出过长被截断。清单不等于已读证据；不带 ListOnly 时仍可输出完整恢复文本供人工使用。文件注入保证入口有机会进入上下文，不能证明模型已经理解全部规则；结构门禁、行为测试和审查分别补足证据。没有客户端加载能力时，才在该客户端设置一次固定入口“先读工作区根 AGENTS.md 并完成恢复”；不要把项目进度复制进固定提示。

## 自动选择分工

| 分支                 | 恢复领域    | 默认修改范围                                                             |
| -------------------- | ----------- | ------------------------------------------------------------------------ |
| main / master        | integration | 已授权的协作、契约、集成与验收；新业务仍需具体任务                       |
| codex/server-*       | server      | apps/server、server 模块记忆、CURRENT 的 Java 区块、本任务 session       |
| codex/web-*          | web         | apps/web、web 模块记忆、CURRENT 的 Web 区块、本任务 session              |
| codex/ai-*           | ai          | apps/ai-service、ai-service 模块记忆、CURRENT 的 AI 区块、本任务 session |
| 其他 / detached HEAD | 未识别      | 只读恢复；根据用户任务确认领域后再改文件                                 |

恢复参数 `-Role` 只选择阅读材料，不授予写权限。任务中的明确修改范围优先；锁文件、跨服务测试、演示数据等按任务分配，不因默认范围漏列而隐式禁止必要工作。修改范围是协作约定，目前没有文件系统级写入隔离门禁。

每个工作区只允许一个活跃执行器写入。根规则、公共契约、Compose、CI、公共脚本和根配置由集成方协调；开发方先提交变更需求，协调确定维护分支，避免多个分支独立改写。架构和权限取舍由用户确认，正式结论写入 docs 或 ADR。

## 每次会话自动执行

1. 开始：读取六入口、本指南、所属模块和 CURRENT 引用的相关 session；核对目录、分支、HEAD、未提交变更、主线差异。报告已集成进度、本领域任务、基线、风险和验收。Restore 只读，不自动 fetch、merge、安装依赖或执行测试。
2. 继续：从 CURRENT 的已授权任务与 session 恢复。只有计划方向而无明确任务时，完成只读核查再请求必要信息；“继续”不能变成无限推进路线图。读取其他分支的已提交记录时标明分支、SHA 和未集成状态。
3. 过程：重要选择、失败、阻塞、切换、暂停和压缩前更新本任务 session 与 CURRENT 所属区块。记录简短结论、证据及精确下一步，不保存完整对话、密钥和原始敏感日志。
4. 收尾：检查 diff 和产物；更新 CURRENT、session 及适用模块；执行 memory Check 和适用测试，正式交付执行完整门禁。分别说明已实现、已验证、已合并及部署范围。

## 记忆归属与过期处理

CURRENT 的集成区块只写主线已接受事实，Java/Web/AI 区块由对应分支维护；其他领域区块是截至所标基线的快照。模块记忆存稳定技术上下文，session 保存任务历史，INDEX 只做导航。集成方在验收后汇总 EVIDENCE、LESSONS、LEARNING 和导航，不要求各分支重复维护全局摘要。

新实质任务复制 session 模板，保留 `handoff:v1` 标记和 Task/Role/Baseline/Contract/Scope 字段；文件名包含领域或独特任务标识，避免并行重名。记录日期、状态、代码版本、命令、结果、环境、跳过项、BLOCKED 和下一步。尚未授权提交时明确记录未提交工作区，不虚构交付 SHA。

检查脚本会验证 CURRENT 四个区块、新版交接字段和导航。它不判断自然语言事实真假，也不能检测所有漏写、越界修改或语义过期。AI 必须对照 Git、代码与证据；发现矛盾时补充纠正并保留历史。相关代码或契约变化后标明受影响证据需复验，不以修改日期新推断内容有效，不因无关变更重跑全部测试。

## 同步、交付与用户职责

工作区文件不共享；代码、规则和记忆通过 Git 一起同步，不共享或软链接 .memory。开发方交付小而完整的任务，用户审查并执行主线合并，集成 AI 验收、汇总记忆。其他分支随后在安全检查点同步新主线，重读变更的规则、契约和记忆，复查任务依赖。

任务开始、交付前以及相关契约或规则变化时检查主线。先保全未提交工作，按已有授权同步；不自动 stash、reset、clean、强推或覆盖冲突。工作分支优先从主线获取依赖，不随意互相合并。冲突按字段含义、代码版本和证据范围归并，不能整份选择某一侧记忆。用户负责目标优先级、跨端取舍和主线合并；AI 负责开发、验证、记录、交接与影响分析。提交和推送仍需用户授权。

同机读取本地 main 只代表本机集成进度；跨机器需按授权 fetch 后检查来源和 SHA，离线时注明未确认远端。未提交的实时进度不经 Git 自动广播；不承诺三端实时同步。

worktree 仅隔离源码。各方的端口、写入型测试数据库、Qdrant collection 和 Compose 项目需分别安排；初期主线统一运行完整六服务联调，开发方独立测试。环境文件和依赖需单独准备，不复制凭据到记忆或 Git。

## CI 与部署边界

[GitHub Actions](../../.github/workflows/ci.yml) 对 push 和 pull_request 自动执行：web 格式/类型/lint/测试/构建、Java verify/Spotless、Python 锁文件/Ruff/mypy/测试/构建、compose 中的布局和 memory Check/工程反例、四个 job 成功后的六服务容器构建与恢复验收。新增协作结构检查通过现有调用进入 CI，无需另设一个同名门禁。开发分支推送后同样触发。

CI 检查结构、代码与覆盖到的行为，不证明 AI 逐条遵守指令或交接文字没有语义过期。数据库测试是否真正运行以日志为准，跳过不等于通过；当前没有面向生产目标的自动 CD，也未在本次变更中启用部署或分支保护。

## 新会话验收一次

在各客户端的正确项目/worktree 新开会话，只输入“汇报当前进度，先不改文件”。观察是否已加载根 AGENTS，并主动读取 CURRENT、规范、所属模块及交接，是否报告真实分支、HEAD、基线与下一步；核对文件内容和实际工具读取记录。自称“读过了”不单独作为证据。

未触发时检查项目工作目录、profile 的指令加载器、覆盖文件、内容预算和文件访问权限；不要先新增另一份指令。现有会话在规则更新后显式重读，不能用旧上下文证明新会话自动注入通过。
