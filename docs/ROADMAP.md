# 最终版开发总计划

目标由[产品蓝图](PRODUCT_DESIGN.md)、[全页面说明](WEB_UI_DESIGN.md)与[开发契约](contracts/README.md)共同定义。下列次序是工程依赖。每项的实现和验收状态维护在[工程交接](../.memory/CURRENT.md)。

## 当前基线

代码、成员权限与启动统一使用工作台接口，模型由用户在本机配置。实际验收范围见[工程交接](../.memory/CURRENT.md)。

| 交付面 | 身份、工程与资料基础                            | 项目业务与验收                                          | 执行文档                                  |
| ------ | ----------------------------------------------- | ------------------------------------------------------- | ----------------------------------------- |
| Web    | W1–W3，认证/路由、能力菜单、项目与成员          | W4–W8，资料、运行、私聊、草稿、引用与真实回归           | [Web](development/WORKSPACE_WEB.md)       |

| AI     | A1–A3，复用解析/索引、服务身份、授权对象与 DOCX | A4–A7，可信检索、双版本判定、Robot 草稿、评测和真实联调 | [AI](development/WORKSPACE_AI.md)         |

## 集成顺序与放行条件

| 检查点        | 可并行启动                                                             | 合流条件 / 证据                                                                                                 |
| ------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| G0 评审与冻结 | 用户已确认六项规则和界面方向，集成方核对交接申请、审批后入队与整包换版 | 设计差异落回唯一文档，2.0.0 契约、样例、页面和三份执行计划为同一 Git 基线；业务规则已定，分发/开发按用户授权    |
| G1 项目和身份 | W1–W3、S1–S2、A1                                                       | J1 通过；管理员与负责人用两套真实账号，管理员无业务内容旁路                                                     |
| G2 资料与依据 | W4、S3、A2/A3                                                          | J2/J3 通过；先有授权对象和签名，再通索引/轮询；提交原件产生零 AI 作业；批准后才入队，检索必须已批准、就绪、可读 |
| G3 复测数据   | W5、S4、A2，S5 可并行做会话持久化                                      | J4 通过；真实 XML 入库并可从 Java 取原始证据，统计一致                                                          |
| G4 可信问答   | W6/W7、S5/S6、A4/A5/A6                                                 | J5/J6 通过；真实模型与 Embedding 下，草稿、引用和双版本判定可在浏览器复核                                       |
| G5 最终交付   | W8、S7、A7、集成与部署配置                                             | J7 隔离/恢复/重放通过，完整门禁和真实三端验收均留证。依赖缺配置则记录缺项，保持未通过                           |

每个开发会话从自己的任务表依次执行，以 provider/consumer 示范请求及失败语义交接。集成方维护公共变更、共享样例与回归；分支基线不同先核对，不用各端私自添加的字段解决联调。开工说明、脚本和签收表见[联调手册](development/PARALLEL_DEVELOPMENT.md)。
